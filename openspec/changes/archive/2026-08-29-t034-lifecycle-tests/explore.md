### Risks

- **H-12 off-by-one at now==start exact:** `canTransition` time guard and `ensureFuture` both use `now.getTime() < start.getTime()` strict `<` (UTC `getTime()`). If a test uses `==` via `toBe` on Date objects or constructs `now` with milliseconds truncation (e.g., `new Date("2026-09-10T12:00:00Z")` vs `new Date("2026-09-10T12:00:00.000Z")` same, but `new Date("2026-09-10T09:00:00-03:00")` is also `12:00Z` — must be consistent). Must assert `08:59` allow and `09:00:00` exact reject with `InvalidAppointmentStateError("El turno ya comenzó")` 409; a lenient `<=` would hide EC-03 regression. Mitigate by injecting deterministic `Date` with explicit `Z` and asserting `rejects.toThrow("El turno ya comenzó")`.

- **canTransition missing cells:** Current `appointmentStateMachine.test.ts` covers 6 valid + ~14 invalid but not exhaustive 32 combos; duplicate route-mock coverage (`CONFIRMADO->CONFIRMADO` etc. via mocked `InvalidAppointmentStateError`) masks that `canTransition` itself might return `true` for a missing cell and still be caught by route mock. Must enumerate every cell as a table-driven `it.each` with plain `canTransition(from,to,role,opts)` without service wrapping.

- **EC-03 past cancel not tested for CONFIRMADO->CANCELADO past:** Existing `appointmentService.test.ts` `cancel R4 borders` only tests `PENDIENTE` start `12:00Z` with `11:59/12:00/12:00:01`.
